# 部署到云端

本项目默认在本地运行（见 [README.md](../README.md)），但同一份代码也可以部署到
Cloudflare Workers 或 Vercel，做成一个随时可用的在线 API。

> 📌 **先读这条**：云端部署和本地运行用的是同一份 `worker.js`，功能完全一致。
> 本地能跑通再去部署云端，排查问题会容易得多。

## 一、部署到 Cloudflare Workers

> ⚠️ **推荐方式：复制代码粘贴部署，不要用 Git 关联仓库部署。**
> 实测 GitHub 关联 CF 部署（Git 集成）容易因入口文件/构建环境问题导致部署失败，
> 且改环境变量后不会自动生效。用下方「复制代码」方式最稳、最快。

### 需要的东西

- 一个 Cloudflare 账号（免费注册：[dash.cloudflare.com](https://dash.cloudflare.com)）
- 一个 `CLINE_REFRESH_TOKEN`（获取方式见主 README）

### 部署步骤（复制代码版，推荐 ✅）

1. 打开本仓库 `worker.js`，**全选复制全部代码**
2. 登录 [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **创建** → **创建 Worker**
3. 名字填 `ClineFreePool`（可自定义）→ **部署**
4. 进入 Worker → **编辑代码** → 删除默认代码，**粘贴**刚才复制的 `worker.js` 全部内容 → **部署**（右上角）
5. **配置环境变量**（重点 ⚠️）：
   - Worker → **设置** → **变量和机密** → **添加**：
     - **机密(Secret)**：`CLINE_REFRESH_TOKEN` = 你的 refreshToken（必填）
       - **支持多账号**：一行一个 token，见下文「多账号」章节
     - **机密(Secret)**：`API_KEY` = 你的访问密钥，例如 `sk-cline-xxx`（必填，可自定义）
   - ⚠️ **保存后必须再点一次「部署」触发重新编译**，变量才会生效！
6. 完成！你的 API Base URL 就是 `https://ClineFreePool.<你的子域>.workers.dev`

### 验证部署

先看环境变量是否生效：

```bash
curl https://ClineFreePool.<你的子域>.workers.dev/v1/health
```

返回 `"api_key_configured":true` 表示 `API_KEY` 已生效，`account_count` 显示已配置的账号数量。

再测一次真实调用：

```bash
curl https://ClineFreePool.<你的子域>.workers.dev/v1/chat/completions \
  -H "Authorization: Bearer <你的API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cline-free/deepseek-v4.1-flash","messages":[{"role":"user","content":"你好"}]}'
```

也可以用浏览器直接打开根路径 `https://ClineFreePool.<你的子域>.workers.dev/`，
用内置控制台查看状态、测模型、发消息。

## 二、部署到 Vercel（可选备一条）

同一份代码可以**同时**部署到 Cloudflare Workers 和 Vercel，互为备份：

- `worker.js` → Cloudflare Workers 入口
- `api/index.js` → Vercel Edge Function 入口（由 `build-vercel.mjs` 从 `worker.js` 自动生成）
- `vercel.json` → 路由重写，把 `/v1/*` 指到 `/api/index`，**不用改**

> 💡 **什么时候值得加一条 Vercel**：CF Workers 域名对 `User-Agent` 挑得凶（非浏览器 UA 直接 `1010`），
> 而 Vercel 域名不挑 UA（curl / python / SDK 默认 UA 都能直连）。如果你的客户端不好自定义请求头，
> 用 Vercel 那条会更省事。

### 需要的东西

- 一个 Vercel 账号（Hobby 免费档即可：[vercel.com/signup](https://vercel.com/signup)）
- 一个 `CLINE_REFRESH_TOKEN`
- **不需要**改代码、不需要 `package.json`、不需要构建命令（Framework Preset 选 `Other` 即可）

### 方式①：Vercel CLI 部署（最快）

```bash
# 1. 安装 CLI（已装可跳过）
npm i -g vercel

# 2. 登录
vercel login

# 3. 拉代码
git clone <你的仓库地址>.git
cd ClineFreePool

# 4. 首次关联项目（交互里选 Create new project，Framework Preset 选 Other）
vercel link

# 5. 配置环境变量（持久化到项目，多账号 refreshToken 一行一个）
vercel env add CLINE_REFRESH_TOKEN production
vercel env add API_KEY production

# 6. 部署到生产
vercel --prod
```

部署完成后地址是 `https://<项目名>.vercel.app`。

> ⚠️ 两个容易踩的点：
> - 环境变量要用 `vercel env add` 写入项目；`vercel --prod --env X=Y` 只对**当次部署**生效，不写进项目配置
> - **改过环境变量后必须重新 `vercel --prod`**，运行时才会读到新值

### 方式②：Dashboard 关联 Git（推送后自动部署）

1. 打开 [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → 选 `<你的用户名>/ClineFreePool`
2. **Production Branch 选 `main`**（本仓库只有 main 一条分支）
3. **Framework Preset 选 `Other`**，Root Directory 保持 `.`（⚠️ 不要填 `api`）→ Build / Output 全部留空
4. **Environment Variables** 添加：
   - `CLINE_REFRESH_TOKEN` = 你的 refreshToken（必填，一行一个支持多账号）
   - `API_KEY` = 你的访问密钥（必填；不设则聊天端点一律 401）
   - 环境至少勾 **Production**（想在预览环境测可再勾 Preview）
5. **Deploy**

之后 push 到 `main` 会自动部署；同样地，**改了环境变量要在 Deployments 里点一次 Redeploy** 才会生效。

### 验证部署

```bash
# 健康检查（无需鉴权）
curl https://<项目名>.vercel.app/v1/health
```

返回 `{"ok":true,"version":"2.2.0","api_key_configured":true,"account_count":1,...}` 即成功。

```bash
# 聊天测试
curl https://<项目名>.vercel.app/v1/chat/completions \
  -H "Authorization: Bearer <你的API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cline-free/deepseek-v4.1-flash","messages":[{"role":"user","content":"你好"}]}'
```

## 三、两版差异对照

| 项 | Cloudflare Workers | Vercel Edge Function |
|---|---|---|
| 入口文件 | `worker.js` | `api/index.js`（自动生成） |
| 入口写法 | `export default { fetch(request, env) }` | `export default async function handler(request)` |
| 环境变量 | `wrangler secret` / Dashboard 机密 | Vercel Env Variables（`process.env`） |
| 路由 | Worker 内置路由 | `vercel.json` rewrites |
| 部署命令 | `npx wrangler deploy` | `vercel --prod` |
| 区域 | Cloudflare 全球边缘 | 文件内 `regions: ["iad1","sfo1"]`（美区） |
| UA 要求 | **必须浏览器 UA**，否则 `1010` | 不挑 UA |
| 域名保护 | 无 | 自动生成的域名受 Deployment Protection 限制，生产别名 `项目名.vercel.app` 公开 |

> ⚠️ 改功能时**只需改 `worker.js`**，然后运行 `node build-vercel.mjs` 自动同步
> `api/index.js`（不要手改生成的文件）。控制台前端则改 `console.src.html`，
> 先跑 `node build-console.mjs` 注入 `worker.js`，再跑 `build-vercel.mjs`。
> 详见主 README 的「项目结构」章节。

## 四、云端专属问题

这些问题在本地运行时**不会遇到**（因为 `localhost` 不经过 Cloudflare 网关）：

### 1. `error code: 1010` —— 必须补浏览器 UA

Cline 的 Workers 网关对**非浏览器 UA 的请求**会直接拦截返回 **`1010`**。
用 curl / python-httpx / 各种 SDK 的默认 UA 去调，很容易撞上。

**解决办法**：在客户端或平台配置里加一条请求头：

```text
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36
```

> 💡 记住：**接 Workers 域名报 1010，第一反应就是补这个浏览器 UA 请求头**。
> 网关只按 UA 判断是不是浏览器，跟你的 API Key 正不正确无关。
> 加完 UA 还报 401，才去查 Key。

### 2. Vercel Deployment Protection 会挡住域名

默认开启时，`项目名-账号.vercel.app`、`项目名-<hash>-账号.vercel.app` 这类域名会被
Vercel SSO 拦截（返回 302 跳 `vercel.com/sso-api`），**只有生产别名
`项目名.vercel.app` 是公开可访问的**。如果三个域名全是 302，
去 **Settings → Deployment Protection** 关掉 Vercel Authentication。

### 3. Vercel 只跑美区

`api/index.js` 里写死了 `regions: ["iad1", "sfo1"]`（美国西部/东部）。
要换区域就改这一行；去掉 `regions` 则跟随 Vercel 默认调度。

### 4. Vercel Hobby 免费档有商用限制

且无 SLA，适合自用/备用。

## 五、环境变量

| 变量名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `CLINE_REFRESH_TOKEN` | 机密 Secret | ✅ | Cline 账号 refreshToken，**一行一个，支持多账号** |
| `API_KEY` | 机密 Secret | ✅ | 客户端访问密钥，自己设一个（如 `sk-cline-xxx`） |

> ⚠️ **`API_KEY` 是必填的。** 早期版本在未配置时会回退到硬编码的
> `cline2api-default-key`，而该值是公开写在文档里的 —— 等于任何知道这个默认值的人
> 都能消耗你的 Cline 账号额度。v1.2.0 起改为 **fail-closed**：未配置 `API_KEY` 时，
> 聊天端点直接返回 401 并提示如何配置，不再回退到公开默认值。
> （`GET /` 控制台、`GET /v1/health`、`GET /v1/models` 不受影响，便于部署自检。）
>
> 变量名必须**完全一致**（全大写、无空格）。修改后**务必保存并重新部署**才会生效。

> 💡 本地运行不需要在这里配置——本地用 `.env.local` 文件，且 `API_KEY` 会自动生成。
> 详见主 README。

## 六、多账号

一个账号的免费额度/限流用完时，想切下一个号？不用改任何东西，
**在 `CLINE_REFRESH_TOKEN` 里一行填一个 token 即可**：

```
第一个账号的 refreshToken
第二个账号的 refreshToken
第三个账号的 refreshToken
```

**工作机制：**

- 🔄 **账号池轮询**：请求轮流使用不同账号（round-robin），分散单账号压力
- ⚡ **额度用完/限流自动切号**：某账号触发 429（`Daily free limit reached`）或空响应，
  **解析上游冷却提示**（如 `Try again in 2h 51m`），按实际时长冷却该账号并切换到下一个，同一请求换号重试
- 🚫 **失效自动跳过**：刷新失败的账号会被跳过，不阻塞
- ✅ **独立缓存**：每个账号各自的 accessToken 独立缓存，互不影响
- 🛡️ **全部冷却不空转**：所有账号均冷却时直接返回 `429` + `Retry-After`（不再打上游空转）
- 单账号时完全兼容，原样工作

**验证：** 部署后访问 `/v1/health`，返回 `account_count` 即当前账号数量，
`accounts_available` 是当前未被冷却、可立即使用的账号数。

> ⚠️ **注意**：多账号只在**真正的多行环境变量**下有效。
> 上面这种写法在 CF Workers 的「机密」输入框、Vercel 的环境变量里都支持
> （直接换行粘贴即可）。但本地 `.env.local` 文件**不支持**——原因见主 README。

### 云端与本地的一处行为差异：设置、账号、统计都不持久

云端**每次部署/重启都会回到初始状态**：控制台「统计」页清零、控制台里改的**设置**
（轮换策略 / 冷却时长 / 默认模型 / system 覆盖 / 请求头 / 上游渠道配置）恢复默认、
在控制台登录的**账号**消失。本地这些都会自动存盘，各写一个 `.local.json` 在用户主目录。

原因是云端没有可写磁盘：这些状态需要有人在进程外存一份（CF 的 KV/D1、Vercel 的外部存储），
而本项目刻意保持「单文件复制粘贴即可部署」，不引入这些依赖。云端下它们只活在当前实例内存里，
且多个 isolate / 多区域时各记各的，数字会偏低。

- 想跨重启保留 → 在**本地**跑（自动写到 `~/.ClineFreePool-state.local.json`
  与 `~/.ClineFreePool-usage.local.json`）。
- 只想知道「今天用了多少」 → 云端够用，额度本身就是按自然日重置的。
- 云端要长期保留账号 → 用 `CLINE_REFRESH_TOKEN` 环境变量，别依赖控制台登录。

> 控制台「设置」页会读服务端的 `persisted` 标记，云端部署时会显示一条明确提示
> 告诉你「改动只对本次实例生效」，不用自己猜。

> 🔓 `GET /v1/health` **不鉴权**，所以它刻意只回「服务在不在、有几个账号」这类计数。
> 账号明细（邮箱、每个账号的用量）在需要 `API_KEY` 的 `GET /v1/status` 里。
> health 仍会公开账号数量与用量规模——介意的话可以改 `worker.js` 里的 health 响应。

## 七、接入第三方平台

把部署好的 Worker 当作 OpenAI 兼容 API 接入第三方平台（以 **AgentScope / QwenPaw**
为例，其他平台同理）：

### 关键：直接用 Workers 域名，不要用自定义域名

- **用 `https://ClineFreePool.<你的子域>.workers.dev/v1`** 作为 **Base URL / API Base**。
- **不要用绑定的自定义域名**（如 `api.llm.xxx.com`）：平台对接时，
  自定义域名可能因证书/路由/鉴权头处理问题导致调用失败或鉴权不过，
  直接用 Workers 官方域名最稳。

### 怎么填

| 字段 | 值 |
|---|---|
| **API Base / Base URL** | `https://ClineFreePool.<你的子域>.workers.dev/v1`（部分平台要求不带 `/v1`，按提示试） |
| **API Key** | 你设置的 `API_KEY` 值 |
| **Model** | `cline-free/deepseek-v4.1-flash`（默认，免费） |

**别忘了加浏览器 UA 请求头**（见上文「云端专属问题」第 1 条），
否则大概率撞 1010。

若平台走标准 OpenAI SDK，直接指定上述 base_url + api_key 即可。
若测试报 401，确认 `API_KEY` 已在平台配置并重新部署过。
